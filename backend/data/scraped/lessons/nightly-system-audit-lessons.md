## EFFECTIVE PATTERNS
- **NEW (2026-05-15)**: Audit route file for duplicate (method, path) registrations via `grep -nE "^router\.(get|post|put|delete|patch)\('" <file> | sed -E "s|^[0-9]+:router\.([a-z]+)\('([^']+)'.*|\2 \1|" | sort | uniq -c | sort -rn`. Any line with count > 1 is a shadowed-route bug. Express resolves first-match, so the later handler is dead code. Tonight: `grep router.<method> backend/routes/ap-coach.js` surfaced `router.get('/usage')` registered twice (lines 58 + 752, PATCH80 + PATCH81 same-day rapid iteration on 2026-05-03). Frontend was calling the legacy schema, so no user-facing break, but exact "rename-half" anti-pattern from ARCHITECTURE.md (patch 165 yesterday). Apply this scan to every route file when a module has 5+ patches in a 2-week window (it accumulates these via rapid iteration). 

- **NEW (2026-05-13)**: When promoting a deprioritized focus area back into nightly rotation (per a recent calibration change), prioritize routes added DURING the dormancy window. The volunteer module shipped batches 138-145 in April; the API-surface deep sweep on 4/25 predated that. Tonight's promotion of API-surface back to twice-weekly caught the /discover-local optional-auth pattern that quietly shipped during the dormant period. Pattern: when running a freshly-rotated-in focus area, `git log --since=<dormancy-start>` on the relevant directory to identify "new since last sweep" surfaces, and audit those first.

- **NEW (2026-05-13)**: Cross-reference code-comment promises against runtime enforcement. The volunteer /discover-local comment said "non-logged-in users can still use this with a hard cap" -- the cap was a phantom (only the route-wide apiLimiter existed, which is per-minute-IP, not per-day-anything). Grep pattern: `grep -rE "cap|limit|throttle" backend/routes/ | grep -i "comment\|//\|/\*"` to find such promises, then audit each one for an actual mechanism. Same pattern caught the 5/5 tokenIndex unbounded growth (a comment said "expired tokens are evicted" while only lazy eviction existed).

- **NEW (2026-05-10)**: Run a URL hygiene scan alongside Rule-1/Rule-2 residue checks. The Rule-1/Rule-2 logic only inspects entries where `_source` parses as a full URL. If `_source` or `url` is structurally malformed (multiple `https://`, whitespace in mid-URL, ` OR ` / ` AND ` / ` / ` separator, or `new URL()` throws), Rule-1/Rule-2 quietly skip the entry and the bug never surfaces. Tonight's becari/donquijote " OR " concatenation in `programs.json` would have stayed hidden indefinitely without this scan. Pattern: per-module, for each entry's `url` and `_source` field — flag if `(v.match(/https?:\/\//gi) || []).length > 1`, or if `^https?` AND contains whitespace, or if matches `\s+(or|and|\/)\s+`, or if `new URL(v)` throws. Adding to nightly rotation.

- **NEW (2026-05-09)**: When tracking Rule-2 residue trajectory, log BOTH sub-buckets (sameUrl and diffHost) separately, not just the net. Tonight: net 81->77 (-4) but the change is entirely in sameUrl (76->72) while diffHost held steady at 5. The architectural mirror (Rule 2 fix) is what reduces sameUrl; diffHost requires manual review. Reporting net alone would have masked which bucket is moving and why. Helps distinguish "data-refresh added properly-cited entries" (good) from "an inject-script regressed and is generating new diffHost entries" (bad).
- **NEW (2026-05-08)**: Rule-2 residue is two buckets, not one. (a) `sameUrl` = `_source === url === homepage` (deferred, "homepage IS program") and (b) `diffHost` = `_source` and `url` are both http URLs but on different hosts (parent-org-vs-program-domain). The Rule-2 architectural mirror only handles same-host fixable cases; diffHost is structurally unfixable from the existing two fields. Watch both buckets — a sudden migration from sameUrl to diffHost (as happened tonight, 5 entries) likely means the data-refresh task is now sourcing from program-domain pages while leaving `_source` as parent-org homepage. Worth flagging if the diffHost bucket exceeds ~20.
- **NEW (2026-05-07)**: Track Rule-2 residue trajectory month-over-month rather than raw count alone. Tonight programs went 77→82 (+5/day); if this pace holds it crosses 230 by 6/1. Sudden 5/day → 30/day inflection would signal an inject-script regression worth investigating. Pattern: log monthly delta in run-history Notable column.
- **NEW (2026-05-07)**: For nightly server boot, `timeout 12 node ./server.js` with minimal env (NODE_ENV=development, CLAUDE_API_KEY=sk-test, JWT_SECRET=…, PORT=3099) reproduces the data-health logger output reliably without hitting external services. The 12-second window catches anything thrown during async-IIFE init plus the data-health pass. Use as default for runtime checks.
- **NEW (2026-05-06)**: Run TWO bare-domain `_source` checks per module — (a) "no http:// prefix" (the original 5/2 filter, fixed by Rule 1) and (b) "full URL with empty path" (the new 5/6 filter, fixed by Rule 2). Different populations, different root causes. Tonight's pattern: `new URL(_source).pathname === '' || === '/'` and no search/hash → flag. Cross-reference against `url` to bucket: (1) url is deeper on same host → fixable, (2) url === _source → "homepage IS the program" deferred, (3) url on different host → manual review.
- **NEW (2026-05-06)**: When extending `normalizeEntry` with a new rule, write the rule as additive to existing logic — don't restructure the existing IF. Test by running the original 5/2 filter post-fix to confirm it still finds 0 (Rule 1 unbroken) AND running the new 5/6 filter to confirm it drops as expected.
- **NEW (2026-05-05)**: When auditing in-memory caches/Maps for unbounded growth, the right grep is `new Map()` + every `.set()` site for it. Cross-reference against eviction sites — both explicit (`.delete()`, `.clear()`) AND implicit (replacement on .set with same key). If eviction is purely lazy (only on access), then any cache entry that's never accessed is a leak. Tonight: `tokenIndex` lazily evicts expired tokens but `buildTokenIndex` re-populates them on every boot. Fix: filter at population time, not eviction time.
- **NEW (2026-05-04)**: Use the official `canonicalKey()` from `backend/services/data-integrity.js` for any duplicate-detection scan — DON'T re-roll `(name|city)` etc. Tonight a hand-rolled `(title|city)` key produced 10 false positives that the canonical `(title|company)` key correctly cleared. Pattern: `import { canonicalKey } from './backend/services/data-integrity.js'` then `canonicalKey('internships', entry)`.
- **NEW (2026-05-03)**: when a deferred data-hygiene flag is "auto-fixable from another field on the same entry," the right place to fix it is in `data-integrity.js normalizeEntry()` — runtime defense + one-time backfill via `validateAndDedup`, not a 19,853-line source-code edit. Pattern: extend `normalizeEntry` for any new deterministic-fix issue.
- **NEW (2026-05-02)**: cross-checking `_source` URL hygiene against `url` rendering paths is high-yield — surfaced 470 internships with bare-domain `_source` (no user impact since `.url` is the rendered field, but violates the canonical-citation rule in CLAUDE.md). - **NEW (2026-05-02)**: re-checking flagged OPEN QUESTIONS against current code is worthwhile — tonight closed the stale `markEventProcessed` unhandled-rejection question (the .catch is already there; prior lesson was overstated).

- **NEW (2026-04-27)**: `cd backend && npm i && timeout 12 node ./server.js` with test env vars is the highest-yield single check. The startup logger surfaces (a) any service-init runtime errors thrown silently in async IIFEs, (b) the data-integrity health-check's duplicate/invalid counts. Tonight it caught two real bugs that no static check would find: the `fsPromises is not defined` reference error in `routes/stripe.js` (broken idempotency persistence → double-credit risk) and 5 exact duplicates in `programs.json` from international HS batches.

## FAILED PATTERNS

- Don't open an issue without proposing a fix or explicitly tagging "DEFERRED — bigger redesign needed."
- Don't auto-fix changes that touch the chat pipeline without a smoke-test commit.
- Don't trust `node -c` alone for runtime correctness — it catches syntax but not undefined-symbol references like `fsPromises` (the reference was inside an async IIFE that gets called at module import time, so even a static lint catches it; but plain `node -c` does not). **Always boot the server.**
- **NEW (2026-05-04)**: hand-rolled canonical keys (e.g., `(title|city)`) produce false-positive duplicate flags — the actual schema uses `(title|company)`. Always import the official `canonicalKey()` rather than re-rolling.
